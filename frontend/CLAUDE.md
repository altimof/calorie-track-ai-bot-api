# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

React 19 + TypeScript 5.9 + Vite 8 frontend for a Telegram Mini App that does AI-powered food photo analysis and calorie tracking. Uses Bun as the package manager and runtime. Deployed on Vercel. The backend is a separate FastAPI service in `../backend/`.

## Commands

```bash
bun run dev                # Vite dev server on port 3000
bun run build              # tsc -b && vite build
bun run check              # type-check + lint + format:check (run before committing)
bun run lint               # ESLint
bun run format             # Prettier
bun run api:gen            # Generate API client from OpenAPI spec via Orval
bun run i18n:validate      # Verify EN/RU translation key parity

# Testing
bun run test                                          # All unit tests (vitest)
bun run test:e2e                                      # Playwright E2E tests (tests/e2e/)
bun run vitest run src/path/to/file.test.ts           # Single test file
bun run vitest run src/path/to/file.test.ts -t "name" # Single test
```

## Architecture

### Entry & Routing

`src/main.tsx` imports `app.css` and i18n, initializes the Telegram WebApp (only when `initData` is present: `ready()`, `expand()`, closing confirmation, header/bg colors), then mounts the React app.

`src/app.tsx` is the core component: creates the `QueryClient` and a `createBrowserRouter` with 4 lazy-loaded pages (`/` -> Meals, `/stats`, `/goals`, `/feedback`) as children of the `AppLayout` layout route. Provider order: `QueryClientProvider` > `TelegramProvider` > `RouterProvider`. `AppLayout` wraps the `<Outlet />` in `ErrorBoundary` + `Suspense` and renders `Navigation`.

### Telegram Integration

`src/providers/telegram.tsx` — `TelegramProvider` handles all Telegram environment sensing in one place:
- Theme detection (Telegram `colorScheme`, then system `prefers-color-scheme`; `setTheme()` override, not persisted). Sets `data-theme` on `<html>`
- Language detection (Telegram `language_code`, then browser locale; `en`/`ru` only; `setLanguage()` override, not persisted)
- Safe areas read from `--safe-area-*` CSS variables, refreshed on resize
- Exposes `user`, `initData`, `theme`, `language`, `safeAreas` via `useTelegram()`

For API requests, `src/api/client.ts` takes the user ID from `window.Telegram?.WebApp?.initDataUnsafe?.user?.id`, falling back to `VITE_DEV_USER_ID` (or a hardcoded ID) in dev only.

### API Layer

Generated by **Orval** from the backend OpenAPI spec. Configuration in `orval.config.ts`.

- `src/api/model/` — TypeScript types generated from OpenAPI schemas
- `src/api/queries/` — TanStack Query hooks generated from OpenAPI endpoints
- `src/api/client.ts` — Custom fetch client (`customFetch` mutator) that attaches `X-Correlation-ID` (per session), `Authorization: tma <initData>` (Telegram's signed launch data; `x-user-id` from `VITE_DEV_USER_ID` instead in dev builds outside Telegram) and `X-Timezone` (browser IANA zone) headers; throws `ApiError` on non-2xx
- Orval input is the local `openapi.json` snapshot

After updating `openapi.json`, run `bun run api:gen && bun run format`. CI runs the same and fails if `src/api/` differs.

### Server State Management

**TanStack Query** (`@tanstack/react-query`) manages all server state:
- Generated query hooks in `src/api/queries/` for data fetching
- Automatic caching, background refetching, and error handling
- No manual `useState`/`useEffect` for API data

### Styling

**Tailwind CSS v4** with `@theme` directive for design tokens. All colors reference Telegram CSS variables (`--tg-*`), never hardcoded. Configuration in `src/app.css` using the CSS-first approach (no `tailwind.config.js`).

### Config

`src/config.ts` — config from `import.meta.env`: `config.apiBaseUrl` (`VITE_API_BASE_URL`) and `config.isDev`.

### i18n

`src/i18n/index.ts` — i18next with nested keys. Translations split into `src/i18n/en.ts` and `src/i18n/ru.ts`. All user-facing text must use `t('key')` from `useTranslation()`. Run `bun run i18n:validate` after adding/changing keys.

### Testing

- Test setup: `src/test/setup.ts` — mocks localStorage, matchMedia, ResizeObserver, IntersectionObserver, Telegram WebApp
- Test utilities: `src/test/utils.tsx` — `renderWithProviders()` wraps components in QueryClient, Router, i18n
- MSW handlers: `src/test/handlers.ts` — mock API responses (used by page tests)
- Framework: Vitest + React Testing Library; tests live in `__tests__/` next to source, plus `src/tests/` (API contract and i18n tests)
- E2E: Playwright, config in `playwright.config.ts`, specs in `tests/e2e/`

## Key Conventions

- **Path alias:** `@/*` maps to `src/*` in imports
- **Unused args:** prefix with `_` (`no-unused-vars` is an ESLint error; `argsIgnorePattern: '^_'`)
- **Lazy loading:** all pages use `React.lazy()`; the `Suspense` boundary is in `AppLayout`
- **CSS theming:** all colors reference Telegram CSS variables (`--tg-*`), never hardcoded
- **API types:** always use Orval-generated types from `src/api/model/`, never define API types manually
- **Server state:** use TanStack Query hooks from `src/api/queries/`, no manual fetch + useState
- **Package manager:** Bun (not npm/yarn). Use `bun install`, `bun run`, `bun add`
